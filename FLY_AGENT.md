# Виртуальная муха: обучение по кадрам игр

В проект добавлен отдельный headless-контур, в котором агент получает только
отрисованный кадр Pygame. Камера, координаты объектов и внутреннее состояние
игры в observation не попадают.

## Что именно реализовано

```text
Pygame Surface
      ↓ RGB
CompoundEye: 721 фасетка яркости + 721 фасетка движения
      ↓
разреженное расширение 4096 Kenyon cells
      ↓
MBON action values
      ↓
команда конкретной игре
      ↓
reward / signed prediction error («дофамин» как инженерная аналогия)
```

- `fly_ai/vision.py` — низкоразрешённый фасеточный CV-сенсор.
- `fly_ai/brain.py` — лёгкая разреженная игровая policy.
- `fly_ai/gpu_brain.py` — опциональное рекуррентное CUDA-поле для живой
  визуализации и управляемой нагрузки GPU.
- `fly_ai/envs.py` — off-screen адаптеры для `knife_hit`, `race`,
  `block_blast`, `darts`, `spider` и `splinter`.
- `fly_ai/train.py` — демонстрации привилегированного учителя, дальнейшее
  TD-обучение, отдельные train/test seed, random baseline и сохранение метрик.
- `fly_ai/play.py` — просмотр сохранённой policy.
- `fly_ai/studio.py` — постоянный интерактивный просмотр: выбор всех игр,
  автоматический перезапуск эпизодов, 3D-муха и активность compound eye.

Учитель доступен только во время сбора демонстраций для Knife Hit и Race.
При оценке policy получает исключительно RGB-кадры. Поля игры используются
средой для reward/termination, как в обычном RL-бенчмарке.

## Быстрый запуск

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-agent.txt
# Для GPU-поля (Windows + NVIDIA, официальная CUDA 12.4 сборка):
.\.venv\Scripts\python.exe -m pip install -r requirements-gpu.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

.\.venv\Scripts\python.exe -m fly_ai.train `
  --game race --teacher-episodes 12 --rl-episodes 0 `
  --eval-episodes 20 --max-steps 300 --kenyon 4096 `
  --learning-rate 0.015 --seed 42 --output-dir artifacts\fly_ai

.\.venv\Scripts\python.exe -m fly_ai.play artifacts\fly_ai\race_fly_agent.npz
```

Все остальные адаптеры также запускаются через тот же CLI, но их большие или
гибридные пространства действий требуют отдельного curriculum; наличие
wrapper-а само по себе не доказывает, что агент уже научился выигрывать.

Результаты каждого запуска сохраняются в `artifacts/fly_ai/`:

- `*_fly_agent.npz` — checkpoint вместе со схемой и метаданными;
- `*_episodes.csv` — каждая train/eval-игра;
- `*_report.json` — сравнение обученного агента со случайной policy.

## Почему не подключён весь FlyWire-мозг

Проект [fly-brain](https://github.com/erojasoficial-byte/fly-brain) — полезный
референс для схемы `sensor → brain → actuator`, но это отдельная тяжёлая
исследовательская симуляция: 138 639 LIF-нейронов, около 15 млн синапсов,
CUDA-GPU, MuJoCo и большие данные коннектома. Её Hebbian plasticity не получает
награду игры и сама по себе не является RL.

Поэтому текущий код нужно называть **мухоподобным CV/RL-агентом**, а не
«оцифрованным мозгом мухи». Число 721 и названия Kenyon/MBON — осмысленная
архитектурная аналогия, но не нейробиологическая реплика.

## Ограничения

- Подтверждённый выигрыш относительно random baseline сейчас есть только для
  Race. Экспериментальный Knife Hit не показал устойчивого улучшения.
- Block Blast имеет 193 macro-action, Spider — длинный горизонт и редкую
  награду, Darts и Splinter дискретизируют исходное непрерывное управление.
- Шрифты и Pygame-рендер могут немного различаться между ОС. Для строгого
  benchmark следует закрепить ОС, версии зависимостей и набор test seed.
- Модели нельзя оценивать на seed, использованных для демонстраций или TD.

## Полученный результат

На 20 невиданных seed обученная policy для `race` получила средний счёт
**349,59** против **129,11** у случайной policy и прожила в среднем 138,45
решения против 81,20. Полный протокол и CSV находятся в
[`artifacts/fly_ai/RESULTS.md`](artifacts/fly_ai/RESULTS.md).

Посмотреть именно проверенную модель:

```powershell
.\.venv\Scripts\python.exe -m fly_ai.play artifacts\fly_ai\race_fly_agent.npz
```

Интерактивная студия запускается двойным щелчком по `START_FLY_STUDIO.cmd`
или командой:

```powershell
.\.venv\Scripts\python.exe -m fly_ai.studio
```

Студия работает до закрытия окна. После аварии или завершения игры следующий
эпизод начинается автоматически. Клавиши `1`–`8` выбирают игру, `Space`
включает паузу, `R` перезапускает эпизод, `F11` переключает полный экран.
Обученный checkpoint сейчас есть только у Race; остальные режимы явно помечены
как демонстрационный эксперт либо случайный baseline.

Клавиша `G` или кнопка в правой части верхней панели переключает CUDA-поле:
`OFF → ECO → RTX → MAX`. Для RTX 2070 стартовый профиль `RTX` содержит
331 776 рекуррентных состояний; ручной `MAX` — 512 000. Интерфейс показывает
реальную загрузку, температуру и частоту циклов. Это вычислительная нейросеть,
получающая текущий сигнал compound eye, но не копия 138 тысяч биологических
нейронов FlyWire и не замена уже проверенной игровой policy.
При 83 °C тяжёлый профиль автоматически сбрасывается в `ECO`.

Режим `3D-полёт` — отдельная бесконечная трасса с кольцами и препятствиями.
Классический RGB-автопилот ищет цветовые контуры прямо на кадре и управляет
набором высоты/снижением и поворотом. Справа отображаются реальные агрегаты
сенсорного слоя, Kenyon cells, MBON-выходов и моторных команд; крылья и лапки
3D-модели анимируются этими же моторными сигналами.

`Neon Drive` — ретрофутуристический псевдо-3D симулятор вождения с кривой
неоновой дорогой, трафиком и контрольными порталами. Отдельный RGB-контроллер
находит на кадре левую/правую границы дороги и силуэты машин, после чего
выбирает газ, тормоз и рулевую команду без доступа к координатам трассы.

## Ночное обучение Neon Drive

Отдельный DQN учится безопасным перестроениям по двум пиксельным каналам:
яркости кадра и движению. Координаты машин не входят в observation. RGB-драйвер
помогает только в начале как демонстратор, затем его вероятность плавно падает
до нуля. Replay-buffer хранится на диске, checkpoint и статус обновляются во
время работы; после сбоя команда продолжает последний запуск:

```powershell
.\.venv\Scripts\python.exe -m fly_ai.train_neon_night --hours 8
```

Для полностью автономного запуска с автоматическим восстановлением процесса:

```powershell
.\.venv\Scripts\python.exe -m fly_ai.watch_neon_night --hours 8
```

Артефакты находятся в `artifacts/fly_ai/neon_night/`: `status.json`,
`episodes.csv`, `checkpoint_latest.pt`, `best.pt`, `replay/`. После появления
`best.pt` Studio автоматически использует обученную DQN при следующем запуске.
Для публикации используется компактный inference-checkpoint
`artifacts/fly_ai/neon_drive_dqn_best.pt`; Studio предпочитает его полному
training-checkpoint, если оба файла присутствуют.
